# Conduite p16, records et réseau

Le 22 novembre 2026, le jeu attribue **p16** à la conduite des monoplaces du commit `c38a28c`, avec les réglages de suspension et d’envol, le replacement et les dernières corrections de l’IA déjà présents. La référence p15 remonte à la 0.2.62. Ses empreintes et ses fichiers de classement restent consultables. [Source du témoin p15](https://github.com/M4D135/bitume/commit/3d124e7a479d5af7d3dcce7391aeaa9d4d97356a) · [Conduite retenue pour p16](https://github.com/M4D135/bitume/commit/c38a28c34921447e9025b55457587ac92476c795)

## Mesure indépendante

Trois courses de 18 secondes simulent douze voitures avec PhysX 5.12.0 au pas de 1/120 s. Elles couvrent Val-Brûlé sur le sec, Port-Sable sous la pluie et Baïkal dans la neige. Sur le même Mac ARM, les anciens et nouveaux replays donnent des empreintes différentes dès la première seconde de Val-Brûlé. Les trois parcours du témoin c38a28c donnent **54/54 empreintes identiques à p16** sur Node 24.18.0 Darwin ARM64 et sur Node 24.22.3 Darwin x64 sous Rosetta.

Le jeu et le témoin s’exécutent chacun dans un processus neuf sur la machine testée. L’archive contient les modules JavaScript et le banc du commit identifié. Le banc contrôle les SHA-256 des quatre fichiers FERRO communs avant de les copier dans son répertoire temporaire. Il compare les poses et vitesses natives, les suspensions, les états, contacts et événements, les géométries, les statistiques et les bilans. La fixture enregistrée contient aussi les valeurs de Darwin ARM64. Les autres environnements comparent directement les résultats aux sources d’origine exécutées chez eux. Le témoin reste hors de la page HTML du jeu.

```sh
node verifications/determinisme-simulation.test.mjs
node --test verifications/records-physique.test.mjs verifications/prets-enligne.test.mjs
```

La commande `node tools/qualification/archiver-physx-p16.mjs` extrait de nouveau l’archive depuis le commit dans un clone complet. Le contrôle porte sur l’empreinte du contenu décompressé, indépendante de la version de gzip.

## Données conservées

| Données | Comportement |
|---|---|
| Tours et fantômes p15 | Les clés `bitume.records.p15` et `bitume.fantome.p15.*` demeurent intactes. Les tours simples sont exprimés en secondes et convertis en millisecondes lors de leur lecture dans l’historique enrichi. Un ancien tableau sans identifiants garde ses indices historiques sous les noms `circuit_N`. |
| Records p16 | Le nouveau meilleur tour et le fantôme se rangent sous `bitume.records.p16` et `bitume.fantome.p16.*`. Le jeu compare les temps d’une même physique. L’API permet de sélectionner expressément p15 pour consulter un ancien classement. |
| Historique enrichi | `bitume.records.v2` reste accessible en lecture. Les nouvelles écritures utilisent `bitume.records.v2.p16`. Un ancien onglet peut continuer à enregistrer ses propres résultats sans écraser les nouveaux. |
| Championnat | Le score, les manches et les sauvegardes de progression gardent leur format et leur clé. |
| Réseau | Les messages de préparation et de départ annoncent l’identité du circuit, la révision complète des sources et la version physique. L’invité refuse une physique différente ou absente avant le départ. |

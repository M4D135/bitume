# 03 → 00 — raccord du menu arcade

## Livrable et base

`03-menu.patch` propose exclusivement les raccords de `src/jeu.js` et `construire.py`.
Base relue : `1c71bb341d20df4328e5178497503ee4ad26a131` ; les sources de ces deux fichiers sont inchangées
sur la branche 03. Le patch est vérifié par `git apply --check`. **Il n’est pas appliqué dans les sources
partagées de la branche 03**. Cette livraison conserve p15 et FERRO 0.3.15 ; elle ne constitue pas un build jouable publié.

Intégrer les quatre sources possédées par 03, puis ce raccord, dans le candidat de 00. Les travaux concurrents de
01/02/04 sur `jeu.js` doivent être conciliés par points d’appel, jamais remplacés en bloc.

## Points d’appel

| Endroit | Raccord | Comportement attendu |
|---|---|---|
| `construire.py`, après `navigation-menu.js` | Charger `menu-arcade.js` avant `jeu.js` | Aucun autre module ni verrou moteur ne change. |
| Initialisation des réglages | `B.menuArcade.normaliserTroll(reglagesEnregistres)` | Deux choix indépendants persistants ; valeurs inconnues ramenées aux défauts. |
| Section écrans | `B.menuArcade.installer(preparation, {retour, actualiser})` | Un seul contrôleur de quatre étapes. `actualiser` remplit le bilan et les choix ; il ne rappelle pas `actualiser()`. |
| `aller(nom)` | Fermer la saisie manette ; préserver/réinitialiser l’étape selon provenance | Nouvelle préparation : Circuit. Retour des réglages : étape conservée. Chaque sortie suspend l’aperçu. |
| `remplirPreparation` / `majPreparation` | Cartes légères et `menuArcade.trace(...)` | Aucun canvas par carte ; numéro, nom, biome, distance catalogue. Seul le circuit sélectionné fournit la géométrie et la fiche réelles de l’aperçu. |
| `naviguerManette` | `valider` et `demarrer` | A sur le circuit choisi passe à Conditions. Start avance jusqu’au bilan puis lance ; jamais de départ depuis un bouton masqué. |
| Entrées du rappel d’image | `lireAutresManettesMenu(...)` | Les contrôleurs supplémentaires naviguent avant course. Les appareils déjà affectés J1/J2 sont exclus, les fronts tenus à connexion/changement d’écran sont consommés. |
| `retour()` | `menuArcade.retour()` avant quitter la préparation | B/Échap/retour : une étape en arrière ; depuis Circuit, titre ou salon selon mode. |
| `image(t)` | `menuArcade.image(t, ecran==='preparation', leger)` avant l’arrêt des menus opaques | 3D projetée seulement sur Circuit visible, cadence/résolution bornées par le module ; titre/préparation/réglages/salon/prêts ne rendent ni ne simulent la vitrine. |
| Titre | `majAttente()` reste avant l’arrêt des menus opaques | Démo automatique après cinq secondes, musique limitée au titre. Course/démo/pause/résultats suivent leurs chemins existants. |
| Choix de circuit et conditions | Retirer les appels `lancerVitrine` | Aucun décor lourd reconstruit lors d’un simple choix. Le vrai départ construit la scène choisie sous le voile existant. |
| `BITUME_JEU.menuArcade` | Exposer seulement `menuArcade.stats()` | Qualification : étape, compteur d’images, points, rotation, dimensions et pause, sans API permettant de piloter une course. |

`B.navigationMenu.fermerSaisie(document, false)` ferme le brouillon quand l’écran change, sans rendre le focus
à un champ désormais masqué. `options.demarrer` est ignoré tant que le clavier manette est ouvert. Le même
garde-fou de doubles appuis couvre A et Start. Les contrôles natifs, la reconfiguration et les commandes de
course J1/J2 sont conservés.

## Troll et préparation en ligne

Contrat de données et limites : [03-TROLL.md](03-TROLL.md). Le raccord sait enregistrer les choix, les montrer
dans la préparation et dans `prets`, retirer l’état prêt après une modification et présenter un bilan fidèle.
**Il ne remplace pas le déclencheur de geste, les IA ni le protocole réseau de 01/00.**

Le bouton d’essai est activé seulement si l’instance audio possède `klaxon(type, options)` ; sinon il est
désactivé avec « Aperçu sonore indisponible. ». Aucun klaxon de remplacement ni fichier audio n’est créé.

```bash

git apply docs/reprise/PARALLELE-2026-11-20/raccordements/03-menu.patch
node --check src/jeu.js
python3 -m py_compile construire.py
node verifications/navigation-menu.test.mjs
node verifications/menu-arcade.test.mjs
node verifications/manette.test.mjs
node verifications/commandes-partage.test.mjs
node verifications/prets-enligne.test.mjs
node docs/reprise/PARALLELE-2026-11-20/raccordements/03-raccord.test.mjs .
```

Résultats du raccord au 20 novembre : **39/39 manette, 47/47 commandes partagées, 63/63 prêts en ligne,
14/14 contre-tests du raccord**. Ces derniers exécutent les vraies fonctions proposées avec DOM, entrées et
horloge simulés : choix/persistance J1/J2, retrait prêt, audio absent/disponible, bilan, cinq menus opaques,
timer démo et fronts des contrôleurs. Ils ne prouvent ni une manette physique ni le rendu WebGL.

La qualification navigateur dédiée applique ce patch dans sa copie et construit localement sans publier le
build commun. Vérifier visuellement les quatre étapes en bureau, portrait et paysage ; aller/retour clavier,
tactile et deux manettes simulées ; aucun dessin FERRO caché ; choix restaurés au rechargement ; vrai départ et
pause. Les captures et le résultat CI sont consignés par 03 dans son état.

## Réserves précises

- Le préchauffage initial existant prépare encore une première scène avant le titre ; il n’est pas supprimé.
  Le rendu continu et les reconstructions déclenchées par les choix du menu sont arrêtés. Revoir l’amorçage
  séparément si 00/02 veut supprimer aussi cette première préparation.
- Le titre doit rester opaque comme le CSS de 03 ; si 00 rétablit un fond de course visible, il faut réexaminer
  la politique de dessin. Pause et résultats ne sont pas assimilés aux menus opaques.
- L’assemblage de Troll complet dépend de 01/00. Aucun son simultané, geste sélectionné, IA ou transmission
  distante ne doit être annoncé livré au seul motif que les champs du menu sont présents.
- Manettes physiques, audio entendu, réseau entre machines, Xbox et GPU Intel restent non qualifiés ici.
